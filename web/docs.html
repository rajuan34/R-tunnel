R-Tunnel Documentation

A lightweight, personal ngrok-style temporary HTTP/HTTPS tunneling service architected specifically for Render Web Services and Android Termux.

1. Architecture Overview

Render Web Services publicly expose HTTP/HTTPS and support WebSocket upgrades. Arbitrary TCP port forwarding is not supported. R-Tunnel bridges this by implementing a bidirectional multiplexed protocol over persistent WebSockets:

Termux Local HTTP Server (e.g. 127.0.0.1:8080)
   ↕ Local HTTP Loopback
Termux Tunnel Client (rtunnel CLI)
   ↕ Persistent Secure WebSocket (WSS)
Render Tunnel Server
   ↕ Public HTTPS URL (Subdomain or /t/:id)
Internet User / Browser

2. Termux Client Setup

Installation

pkg update && pkg install nodejs
git clone https://github.com/rajuan/r-tunnel.git
cd r-tunnel/client && chmod +x install.sh && ./install.sh

Authentication

rtunnel login
# Prompts for Server URL (e.g. https://r-tunnel.onrender.com)
# Prompts for Master Token

Running a Tunnel

rtunnel 8080

3. Supported Lifetimes

Tunnels are temporary and automatically expire server-side. Allowed durations:

  • 30m — 30 Minutes
  • 1h — 1 Hour (Default)
  • 2h — 2 Hours
  • 3h — 3 Hours

4. Security Safeguards

  • Strict SSRF Protection: The tunnel client strictly connects only to 127.0.0.1 / localhost. Arbitrary LAN/WAN targets are rejected.
  • No Open Proxy: Render server only forwards traffic for active, authenticated client WebSocket connections.
  • Binary Integrity: Transparent Base64 encoding ensures images, audio, and binary streams are never corrupted.
  • Rate Limiting & Max Body Size: Configured to prevent memory exhaustion and abuse.
